# 大模型协作记录

> 本记录说明本作品中人工与大模型智能体的协作方式、指令设计、人工把关过程与协作规模。
> 统计范围为本机开发日志（2026-09-17 ～ 2026-10-31，116 个开发会话）；文档撰写阶段单独统计，不计入开发期数字。

## 1 协作模式与分工

本作品采用“人工主导、智能体执行”的协作模式，分工如下：

| 角色 | 职责 |
|---|---|
| 项目负责人（人） | 选题与总体方案、技术路线取舍、验收口径制定、关键节点评审、板端实验与现场反馈、风险处置 |
| 主智能体 | 任务书拆解、团队编排、代码与脚本实现、仿真与综合的批量执行、证据整理、文档初稿 |
| 并行子智能体 | 前端、代码生成、RTL、验证、文档等专项子任务 |
| 后台作业 | 长周期编译、综合、仿真等异步任务 |

工作流分五步：任务书 → 执行 → 交接 → 门禁 → 沉淀。

1. **任务书**：目标、边界、必读文档、步骤、验收标准、交付物六项齐全；
2. **执行**：按任务书实施，长任务以后台作业编排，必要时并行分工；
3. **交接**：记录结论、证据路径、未闭合项、下一阶段建议；
4. **门禁**：仿真（0 mismatch）、时序（0 失败端点）、板端（逐位比对）三级验证；
5. **沉淀**：问题与修复写入项目规范与技能包，成为下一轮任务的前置检查。

所有智能体产出均须经人工验收后才能进入下一环节；方向判断与验收决策始终由项目负责人做出。

## 2 指令设计

交互以结构化指令为主，避免开放式对话。代表性指令类型如下：

| 指令类型 | 设计要点 | 作用 |
|---|---|---|
| 任务书 | 六要素齐全，声明不得越界开展下一阶段工作 | 任务可执行、可验收、可交接 |
| 交接指令 | 要求输出结论、证据路径、未闭合项与下一任务书 | 跨会话保持上下文一致 |
| 验收口径 | 阶段验收，结论必须标注 pass / fail / partial / not_run | 减少无效等待，统一证据标准 |
| 纠错指令 | 指出具体现象，要求先解释原因再给出修复方案 | 快速定位问题，防止错误结论扩散 |
| 范围控制 | 明确任务结束点与并行子任务停止条件 | 控制并行规模，避免结果分叉 |

指令设计遵循三条原则：**可执行**（每条指令对应可检查产出）、**可追溯**（要求文件路径与命令）、**留痕**（重要结论写入交接文档）。

## 3 人工把关与纠错

智能体在长周期任务中会出现判断偏差，本项目的关键纠错均由人工评审或证据复核触发：

| 问题 | 发现方式 | 纠正措施 | 结果 |
|---|---|---|---|
| 资源门槛缺乏依据 | 项目负责人质疑并追问数据来源 | 按历史运行数据重新测算并下调门槛 | 恢复施工，避免继续等待 |
| 核级 OOC 被当作平台完成 | 项目负责人追问是否连接 Block Design、能否生成位流 | 补做平台 Block Design、约束与全片实现 | 平台实现收敛，固定样本板测通过 |
| 跨时钟域复位处理不当 | 综合报告出现违例，证据复核时发现 | 复位按域拆分，XPM 复位仅由写时钟域驱动 | 综合时序恢复，CDC 重构后收敛 |
| 板端输入布局错误 | 板端比对时 6 个输出头全部不一致 | 定位输入排布并修正驱动 | 6/6 一致，板测通过 |
| 运行环境改变 manifest 哈希 | 复算 manifest 时发现不一致 | 清理缓存、固定运行参数并写入检查单 | 校验恢复通过 |

上述问题的共同点是：智能体可以完成实现与验证，但结果是否可信、是否达到验收标准仍需人工判断。项目负责人通过质疑数据来源、追问交付完整性、核对证据文件，纠正了多处偏差；这些判断随后被固化为任务书模板与技能包中的检查项。

## 4 协作规模

| 指标 | 数值 | 说明 |
|---|---|---|
| 开发会话 / 有效指令 / 助手消息 | 116 / 459 / 18,147 | 45 天、9 个工作目录 |
| 工具调用（含子调用） | 约 2.75 万次 | 以命令执行、文件读写与检索为主 |
| 并行团队 / 成员 / 共享任务 | 17 / 68 / 71 | 并行开发与文档整理 |
| 记录在案的修复 | 15 类 | 均形成检查项或技能 |

## 5 边界说明

1. 统计仅覆盖本机开发日志，空会话与无关会话已剔除；
2. 同一回答的模型归属无法逐条追溯（日志仅有模型切换记录）；
3. 板端数据由现场人员回传，并与仓库文档交叉核对；
4. 智能体产出均经人工验收后采信；
5. 技能包为项目结束后提炼，开发期间未直接调用技能工具。
